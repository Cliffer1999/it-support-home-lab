# Troubleshooting Method

A good Service Desk response is repeatable, safe and easy for another technician to understand.

## 1. Identify the Problem

Ask focused questions:

- What were you trying to do?
- What exactly happened?
- What error message appeared?
- When did it last work?
- Has anything changed recently?
- Is anyone else affected?
- Can the issue be reproduced?

## 2. Establish Scope and Priority

Determine whether the issue affects:

- one user
- one device
- one location
- a team
- the entire organisation

Business impact matters. One user's cosmetic application issue is different from an organisation-wide authentication outage.

## 3. Collect Evidence

Examples:

- screenshots/error text
- IP configuration
- application status
- Task Manager resource usage
- Windows Event Viewer entries
- account state
- device state
- timestamps

## 4. Build and Test a Hypothesis

Start with likely, low-risk causes. Change one meaningful variable at a time where possible. Avoid destructive actions such as deleting profiles or resetting devices before simpler checks are exhausted.

## 5. Implement the Fix

Record the exact action. If elevated privileges or a change outside L1 authority is required, stop and escalate under the organisation's process.

## 6. Verify with the User

A technical check alone is not enough. Reproduce the original user task and confirm the service works as expected.

## 7. Document and Close

A useful closure note contains:

- reported symptom
- scope
- checks performed
- relevant results
- action taken
- root cause if known
- verification result

## Escalation Standard

An escalation should answer: **What does the next technician need to know so they do not repeat my work?**

Include evidence, timestamps, affected users/devices, commands already run, results, suspected component and business impact.
